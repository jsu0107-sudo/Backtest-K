# 백테스트K 변경 이력

작업 도구(Claude Code, Codex 등)와 무관하게 모든 에이전트·개발자가 공유하는 변경
추적 문서다. 기능 커밋을 만들면 이 파일에 항목을 추가한다. 데이터 자동 갱신
커밋(`chore(data)`)은 기록하지 않는다.

## 2026-08-05 — 자동 데이터 갱신 복구

### `9bcd4a4` Node 버전 간 골든 해시 안정화 + 생성물 동기화

- **실패 원인**: 장기 누적 시계열의 15번째 유효숫자에서 Node 20·24의 부동소수점
  결과가 달라 전체 객체 SHA-256 검증이 실패했다. 핵심 지표와 데이터 개정 검사는
  통과했지만 이 오탐 때문에 2026-07-27 이후 데이터 커밋이 차단됐다.
- **검증 수정**: 전체 시계열 해시에 한해 유한수를 유효숫자 14자리로 정규화했다.
  핵심 지표는 원래 값 그대로 엄격 비교하고, 입력 수익률 개정 감시 허용오차도 기존
  `1e-5`를 유지한다. Node 20·24에서 같은 해시가 생성됨을 확인했다.
- **자동 생성물 동기화**: 데이터 갱신 시 `npm run precompute` 뒤
  `npm run build:single`을 실행하고 `npm test` 전체를 검증한다.
  `backtestK_single.html`과 `SHA256SUMS.txt`도 데이터 커밋에 포함한다.
- **불변 조건**: `core/` 계산 산식, 공유 코덱 v1/v2, `data/*.json` 계약과 기존
  정적 호스팅 구조는 변경하지 않았다.

### `1b1c8cd` 공공데이터포털 일시 장애를 비차단 상태로 전환

- **추가 실패 원인**: 골든 해시 문제를 고친 뒤 공공데이터포털 공식 종가 API가
  3회 연속 시간 초과되어, 정상 생성·검증된 7월 월 수익률의 커밋이 다시 차단됐다.
- **조치**: 예약 작업은 공식 API가 일시적으로 응답하지 않으면
  `data/official_verification.json`에 `status=unavailable`을 기록하고 데이터 게시를
  계속한다. 데이터 화면에는 **공식시세 대사 일시 확인 불가**로 표시되며 다음 평일에

  테스트 12건과 Python 테스트 16건이 모두 통과했다.
- **불변 조건**: 실제 공식 종가 불일치 집계, 정적 데이터 계약, `core/` 계산 산식과

## 2026-07-22 — Phase 0 (첫 진입 이탈 최소화)

### 몬테카를로 화면 정비

실측 결과 7건을 수정했다. 계산 산식은 그대로다.

- **재현성**: 시드를 `Date.now()`에서 **입력 조건 해시**로 바꿔, 같은 조건이면 항상 같은
  결과가 나온다. (기존에는 같은 조건 재실행에 중앙값 596억 → 607억으로 흔들렸다.)
  새 난수가 필요하면 **"다른 난수로 다시 굴리기"** 버튼을 쓴다.
- **시작 자산**: 백테스트 최종 자산을 이어받되 **만원 단위로 반올림**하고(993,366,433 →
  993,370,000), 사용자가 직접 고치면 **이후 백테스트가 덮어쓰지 않는다**(`mcInitialTouched`).
- **목표 자산**: 기본값을 시작 자산의 3배로 잡는다. 예전 기본값(5억)은 시작 자산(9.9억)보다
  작아 **달성 확률이 100%로 고정**돼 지표가 죽어 있었다. 목표 ≤ 시작이면 경고를 띄운다.
- **숫자 표기**: 4개 입력을 메인 화면과 같은 콤마 포맷 + `inputmode="numeric"`으로 통일.
- **계산 상태**: 작업 2의 스켈레톤·소요 시간·실패 안내를 몬테카를로에도 적용
  (1,000경로×40년 = 296ms 동기 계산인데 그동안 아무 피드백이 없었다).
  `beginComputing`/`endComputing`이 대상 상태 요소를 인자로 받도록 일반화했다.
- **4번째 지표 카드**: 인출이 0이면 항상 0%인 "자산 고갈 확률" 대신 **"상위 10% 자산"**을
  보여준다. 인출이 있으면 고갈 확률로 돌아간다.
- **해석 4번째 항목**: 이미 목표를 넘었으면 "필요 적립 0원" 대신 초과액을 표시한다.
- 결과 상단에 조건 요약 한 줄 추가 (`9.9억원에서 시작 · 월 100만원 적립 · 20년 · 500개 경로`).

### 모바일 대응 (Phase 0 작업 3)

375 / 390 / 430px에서 실측 후 수정. 착수 시점 44px 미만 터치 타겟이 **38개**였다.

- **터치 타겟 44px 이상**(767px 이하): 내비·모드·탭·프리셋 칩·버튼·입력·아이콘 버튼.
  체크박스는 라벨 전체(90×44, 141×44)가 터치 영역이라 그대로 둔다. → 남은 위반 **0개**
- **자산 비중 입력에 `inputmode="decimal"`** — 모바일에서 숫자 키패드가 열린다.
- **표 첫 열 고정**: 성과요약·낙폭 순위·연도별 표를 가로 스크롤해도 지표명/연도가 남는다.
  (상관관계 표는 행 머리글이 의미상 고정될 필요가 없어 제외)
- **차트 터치 툴팁**: 마우스 전용(`mousemove`/`mouseleave`)이라 **모바일에서 툴팁이 아예
  동작하지 않던 문제**를 포인터 이벤트로 교체해 해결. 성장·낙폭·연도별·몬테카를로 4종 모두
  터치로 표시되고 손을 떼면 사라진다. 세로 스크롤은 `touch-action: pan-y`로 유지.
  - `setPointerCapture`는 try/catch로 감쌌다. 실패하면 이후 로직이 통째로 중단돼
    첫 터치에서 툴팁이 뜨지 않는다.
- **실행 버튼 하단 고정**(768px 미만 + 원래 버튼이 뷰포트를 벗어났을 때만):
  `env(safe-area-inset-bottom)` 반영, 라벨에 `합계 100.0% · 백테스트 실행`,
  합계가 100%가 아니면 비활성. 데스크톱에서는 `display:none`으로 원천 차단.
  - IntersectionObserver → 좌표 계산으로 교체. 렌더링이 멈춘 탭에서 IO 콜백이 오지 않아
    상태가 어긋났다. 등장 애니메이션도 제거(같은 이유로 바가 화면 밖에 걸렸다).

### 계산 상태 UX (Phase 0 작업 2)

- **스켈레톤**: 계산 중 결과 카드 위에 같은 크기의 오버레이만 얹어 CLS 0을 유지한다.
  120ms가 지나야 붙이므로 빠른 재계산에서는 아예 나타나지 않는다(깜빡임 방지).
  `prefers-reduced-motion`도 존중한다.
  - 프리셋 적용은 "데이터 로드 → 백테스트"로 중첩되므로 깊이 카운터를 둬서
    가장 바깥 호출이 상태를 관리한다. 그래야 모바일에서 가장 긴 구간(데이터 대기)이
    측정·표시에 포함된다.
- **소요 시간**: 결과 헤더에 `0.07초 만에 계산 완료` 표시(기존 "계산 완료" 자리).
- **실패 안내**: 조용히 끝내지 않고 결과 영역 배너 + 좌측 폼에 이유를 남긴다.
  예) "선택한 자산들의 공통 데이터가 6개월뿐입니다(최소 12개월 필요). 상장일이 늦은
  자산을 빼거나 기간을 넓혀보세요. 대상: …". 헤더는 빨간 "계산 실패" 상태로 바뀐다.
- **데이터 폴백 고지**: 카탈로그 로드 실패 시 데모로 조용히 넘어가지 않고
  "합성 데모 데이터로 계산했다"를 결과 화면에 명시한다.
- **구간 단축 즉시 안내**: 자산을 추가·삭제·교체하는 즉시(수익률을 받기 전에도)
  카탈로그 메타데이터로 구간 변화를 계산해 알린다.
- ⚠️ 검증 메모: 프리뷰가 백그라운드 탭이면 `setTimeout`/`setInterval`이 1초로
  클램프되어 120ms 타이머가 늦게 발화한다. 스켈레톤 검증은 폴링이 아니라
  MutationObserver로 해야 한다.
