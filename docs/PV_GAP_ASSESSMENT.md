# 한국판 Portfolio Visualizer 가능성 평가와 실행 계획

평가일: 2026-09-27. 대상: 현재 로컬 코드와 공개 운영 JSON, PV 공식 기능 소개.
후속 구현: [P0 데이터 안전장치 1차](P0_DATA_SAFETY.md). 아래 평가는 구현 전 기준이며,
월말 필터·USD 차단은 로컬 반영했다. 원본 복구·총수익 독립 대사·운영 배포는 아직 미완료다.
유료 계정 내부 기능·국내 경쟁 서비스 전체·사용자 수/재방문율·지불 의사는 검증하지 않았다.
따라서 아래는 제품/기술 적합성 판단이지 시장 성공 확률 예측이 아니다.

## 1. 결론

**국내 ETF 적립식·연금 투자자를 위한 한국형 분석 서비스는 가능성이 있다.
현재 상태를 PV와 동급의 검증된 분석 플랫폼이라고 부르기는 어렵다.**

현재 위치는 실데이터 연결과 재현성 기반을 갖춘 프로토타입이다. 원화 금액, 월 적립,
한국어 설명, 국내 ETF 검색, 공유 스냅숏은 유용한 기반이다. 그러나 데이터 월말 완결성,
총수익 독립 검증, 통화 일치, 장기 시뮬레이션 모형 검증이 먼저 해결되어야 한다.
최적화·팩터 메뉴를 늘리는 것보다 이 문제를 해결하는 편이 제품 가치가 높다.

첫 목표는 PV 전체 복제가 아니라 **한국 ETF로 적립하고 은퇴 때 인출할 때의 비교 도구**다.
PV는 백테스트 외에 최적화/효율적 투자선, 팩터 분석, 전술적 자산배분과 목표 기반
시뮬레이션을 제공한다. 이 범위까지 단기간에 동등해진다고 약속하지 않는다.
[공식 도구 목록](https://www.portfoliovisualizer.com/analysis)

## 3. 우선 해결해야 할 구체적 위험

### P0-A. 월 라벨과 실제 관측일이 다르다

운영 사이트 읽기 전용 조회 결과:

- `/data/assets.json`: `data_as_of=2026-09-15`, `generated_at=2026-09-15T15:35:00Z`,
  `asset_count=150`, `provider_status=provisional`.
- `/data/INDEX_KOSPI200.json`: 마지막 월 `2026-07`, 관측일 `2026-07-16`.
- 로컬 카탈로그는 `2026-08-05`로 운영과 다르다.

평가일 기준 운영 카탈로그는 12일 전이다. 이것만으로 GitHub Actions 실패 원인을
단정할 수는 없다. 그러나 카탈로그의 기준일과 각 자산의 확정 월말 데이터는 별개이며,
7월 중간 관측을 확정 월 수익률처럼 취급하지 못하도록 차단해야 한다.

**개선:** 거래소별 마지막 거래일과 관측일 대조, complete/partial/stale 상태,
종목별 last_complete_month, 허용 지연 초과 시 경고·분석 제외, 마지막 정상 릴리스 보존.
0% 수익률만으로 스테일을 판정하지 않는다. 정상적으로 0%인 달도 존재한다.
화면 전체 배너를 되살릴 필요 없이 결과의 데이터 상태 배지/상세 정보로 제공한다.

### P0-B. 총수익·통화 기준의 비교가 완전히 일치하지 않는다

ETF 수정종가의 분배금 반영은 공급자에 의존한다. `official_verification.json`의
147/147 일치는 로컬에 저장된 과거 원시 종가 대사 결과일 뿐 전체 월 총수익 검증이 아니다.
가격지수 BM에는 경고가 있지만 동일한 경제적 기준의 총수익 BM이 더 바람직하다.

`data/INDEX_SP500.json`은 USD 가격지수다. 현재 계산 경로는 월 수익률을 그대로 사용하며
통화 환산 경로가 확인되지 않는다. 이를 원화 평가액에 적용하면 실제 원화 S&P500 투자와
같지 않다. 국내 상장 해외 ETF의 원화 수익률에 FX를 다시 적용해서도 안 된다.

**개선:** 표시통화/원천통화/환헤지/TR 여부를 데이터 계약에 명시하고, USD 자산에는
`(1+현지수익률)×(1+환율수익률)-1`을 검증된 월 경계로 적용하거나 비교를 제한한다.
공식 분배금·분할 원장 및 분배락/재투자 가정을 버전 관리하고 대표 표본부터 독립 대사한다.
데이터의 공개 조회 가능성과 상업 재배포 권한은 다르므로 공급자별 이용 권한 확인도 출시 조건이다.

### P0-C. 계산 코드와 검증 범위가 아직 나뉘어 있다

본편은 `core/backtest.js`를 쓰지만 공유/랜딩은 `engine.js` 축약 계산 사본이 남아 있다.
몬테카를로 루프와 분위수 계산도 `app.js`에 있다. 동일 명칭의 지표가 달라질 위험과
DOM 의존 테스트 한계가 있다.

**개선:** 산식을 바꾸지 않는 1차 리팩터로 공유/랜딩과 MC를 순수 core로 이동한다.
v1 호환을 유지하고 v2 스냅숏은 재계산하지 않는다. 손계산 예제, 독립 Python 계산,
동일 입력 데이터로의 교차 대사, 비용/입출금/결측/회복 경계 테스트를 추가한다.
산식 개정은 별도 버전으로 공개하며 골든을 새 결과에 맞춰 무조건 바꾸지 않는다.

### P1. 몬테카를로의 확률은 모형 의존적이다

현재 `runMonteCarlo`는 최소 12개월의 포트폴리오 수익률에서 월을 독립 추출한다.
월간 자기상관·위기 지속성을 보존하지 않는다. 자산별 공동 경로 및 동적 리밸런싱을
매 경로에서 재계산하는 모형도 아니다. 정규근사 수익률은 ±75%로 잘린다.
고정 정액 현금흐름을 사용하고, 물가연동 인출이나 기대수익률 변화 시나리오는 없다.

**개선:** 우선 입력자료 기간/방법/시드/데이터 버전 노출, 표본 부족 경고,
독립 월 bootstrap과 블록 bootstrap 비교, 기대수익률 민감도, 물가연동 인출을 제공한다.
작업은 Web Worker로 옮겨 5,000~10,000회 경로를 성능 측정 후 제공한다.
500회·성공률 50% 근처의 단순 Monte Carlo 표준오차는 약 2.24%p,
정규근사 95% 오차 범위는 약 ±4.38%p다. 이는 모형 오차를 포함하지 않는다.
500회 모두 성공해도 현실 성공확률 100%를 보장하지 않으므로 '표본 내 전 경로 달성'을 함께 표시한다.

## 4. 단계별 실행 계획

기간은 1명의 숙련 개발자와 데이터/세무 검토 지원을 전제로 한 **추정 작업량**이다.
데이터 계약 체결·검토 대기 기간은 별도이며 일정 보장이 아니다.

| 단계 / 추정 | 산출물 | 완료 조건 |
|---|---|---|
| P0 · 2–4주 | 월말 완결성/통화 게이트, 데이터 상태, 릴리스 검증 | 불완전 월·다른 통화 무표시 비교 0건, 일관된 last_complete_month, 배포 JSON/릴리스 ID 대조 |
| P0 · 병행 2–6주+ | 분배금 독립 대사·데이터 사용권 검토 | 주식/채권/금/해외/분배형 표본 20종 이상, 오차 예산 정의·초과 전건 원인 설명, 권한 확인 전 상용화 보류 |
| P1 · 2–3주 | core 통합, 독립 산식 대사, CI/브라우저 회귀 | 본편/공유 v1/랜딩 동일 입력 동일 지표, v2 불변, 주요 모바일 흐름 자동 검사 |
| P1 · 2–3주 | A/B/C 포트폴리오 비교, 다중 로컬 저장·JSON 내보내기, rolling 1/3/5년 | 같은 기간·통화·현금흐름으로 비교, 비교 조건과 기간 축소 이유 명시 |
| P1 · 3–4주 | MC core/Worker, 블록 추출, 민감도·인출 개선 | 고정 시드 재현, 경로 수 수렴 검사, 375px UI, 기준 기기/최대 경로에서 입력 반응성과 실행시간 측정 |
| P2 · 4–8주+ | 계좌·세금·환율·은퇴 현금흐름 | 시행일/출처/제약이 있는 규칙 버전, 전문가 검토 사례 통과, 원화 세후 결과 비교 |
| P3 · 이후 | 최소분산/위험균형 → 효율적 투자선 → 팩터/전술 전략 | out-of-sample/워크포워드, 생존·선행편향 통제, 비용 포함 비교를 출시 게이트로 사용 |

권장 첫 90일은 P0와 core 통합, A/B/C 비교, 제한된 MC 개선에 집중한다.
계좌 세무 엔진·모든 최적화·팩터까지 동시에 완성하는 일정은 권하지 않는다.

## 5. 운영 구조와 비용 현실

정적 JSON + GitHub Actions + Vercel + 브라우저 계산을 당분간 유지한다.
로컬 다중 저장/비교, Worker MC, 간단한 최적화는 별도 서버 없이 구현할 수 있다.
그러나 데이터 라이선스, 사용자 인증/동기화, 유료 결제, 지원 업무, 트래픽에 따라 비용이 발생할 수 있다.
**서버·DB 0원 목표는 가능하더라도 서비스 전체 비용 0원·장애 지점 0개는 보장할 수 없다.**

무료 구조에서도 마지막 정상 릴리스, 재시도 한도, 갱신/검증/배포 각각의 상태,
운영 JSON freshness 및 manifest 일치 검사가 필요하다. cron 존재는 갱신 성공 증거가 아니다.
관리 데이터 화면의 메뉴 숨김은 접근 통제가 아니며 민감 정보는 공개 정적 파일에 두지 않는다.

## 6. 시장성을 검증하는 작은 실험

- 한국 ETF 적립/연금 사용자 10–15명에게 같은 과제(전략 비교→조건 변경→결과 설명)를 수행시킨다.
- 초기 가설 목표: 도움 없이 80%가 완료하고, 데이터 기준/확률 한계를 설명할 수 있는지 확인한다.
- 기존 `page_view`, `backtest_run`, `result_share`는 유지한다. 이 이벤트 수만으로
  고유 사용자 재방문/유료 전환을 추정하지 않는다. 별도 동의된 인터뷰/패널로 4주 재사용과 지불 의사를 검증한다.
- 정확성 문제를 해소한 후 사용성·반복 사용이 확인될 때 저장/보고서 유료화를 시험한다.
- '한국판 PV'라는 이름보다 '국내 ETF 적립·연금 전략을 같은 조건으로 비교한다'는 구체적 문제 해결을 먼저 검증한다.
